# 改名方案 · 冻结契约（v2.0.0 "去上游痕迹"）

> 冻结：**2026-10-16** ｜ 用户裁决：协议 id 也改、Blender 侧 addon 也改名、历史重写 + force-push
> **本文件是唯一真源**：三处（addon / 插件 runtime / 文档）都按这里的名字改，任何一方不得自创名字。

## 1. 命名映射（**逐字使用**）

### 1.1 Blender 侧 addon

| 项 | 旧 | 新 |
|---|---|---|
| 文件名 / 模块名 | `blender_mcp.py` | **`dsh_blender_bridge.py`** |
| `bl_info["name"]` | `"MCP for Blender"` | **`"DSH Blender Bridge"`** |
| **标识前缀**（全部 34 个） | `blendermcp_` | **`dshbb_`** |
| 注册类（`bpy.types.*`） | `blendermcp_server` | **`dshbb_server`** |
| 5 个场景开关 | `blendermcp_use_polyhaven` 等 | **`dshbb_use_polyhaven`** 等 |
| 其它 prefs / handler / timer 名 | `blendermcp_*` | **`dshbb_*`** |
| UI 里露出的产品名 | `MCP for Blender` | **`DSH Blender Bridge`** |

- 机械替换规则：**全局 `blendermcp_` → `dshbb_`**（前缀替换，含类名/属性名/handler/prefs/`bpy.types` 赋值与读取）
- 显示串 `MCP for Blender` → `DSH Blender Bridge`（UI/面板/日志/错误文案）
- ⚠️ **MIT 合规（不可越过）**：addon 源码里的**版权声明与 MIT 许可证文本必须原样保留**（`"author"`、`"license"`、文件头注释里的 upstream 版权）。**只改显示名与标识，不删声明。**

### 1.2 插件侧协议 id 与标签

| 项 | 旧 | 新 |
|---|---|---|
| 协议判别 id | `'ahujasid'` | **`'flat'`** |
| 另一个（不变） | `'category-action'` | `'category-action'` |
| 配置合法值 `CFG.addonProtocol` | `auto｜ahujasid｜category-action` | **`auto｜flat｜category-action`**，并把 `'ahujasid'` 作为**已弃用别名**接受（归一化为 `'flat'`，不报错） |
| 协议显示标签 | `'ahujasid / MCP for Blender（扁平协议…）'` | **`'直连 addon · 扁平协议（无分帧）'`** |
| 另一实现标签 | `'harveyxiacn blender_mcp_addon（category/action，换行分帧）'` | **`'直连 addon · category-action（换行分帧）'`** |

## 2. 兼容契约（**强制**，防"改一半断链"）

1. **插件侧对 addon 标识双名探测**：
   - 读 5 个开关：先 `dshbb_use_*`，取不到（`None`/`AttributeError`）再回退 `blendermcp_use_*`
   - 探测 server 类：先 `bpy.types.dshbb_server`，再回退 `bpy.types.blendermcp_server`
   - ⇒ addon **未改名**时插件照常工作；addon 改名后也照常工作
2. **协议 id 别名**：`resolveProtocol` 收到 `'ahujasid'` 归一化为 `'flat'`（旧配置文件不炸）
3. **`GATE_FLAGS` 结构不得改变**（测试与 handoff 依赖它）：保持 5 个逻辑名，只改字符串前缀策略
4. **测试同步**：`tests/protocol_selftest.mjs` 里断言 `'ahujasid'` 的地方改 `'flat'`，并**新增一条**断言"`'ahujasid'` 被接受并归一化为 `'flat'`"（防回退失效）
5. **不改的东西**：`blendermcp_*` 在**兼容回退分支**里必须保留（那是"旧 addon"的名字，不是痕迹）；`harveyxiacn`/`blender_mcp_addon` 只用于**另一个第三方实现**的判别回退，其 id `'category-action'` 中性、保留

## 4. 残留判定（验收口径）

- **addon 文件内的允许位**（改不了／不该改，逐条登记）：
  1. **版权与作者署名**：文件头 `# Code created by Siddharth Ahuja…© 2025`、`bl_info["author"]`（含 v1.6 的 `"BlenderMCP"`）、`terms_url` 里的 upstream 链接 —— **MIT 合规，必须保留**
  2. **上游 Premium 服务端点**：`PREMIUM_PRICING_URL` / `PREMIUM_MANAGE_URL_DEFAULT` = `https://mcp-for-blender.com/…` —— **改了 Premium 功能直接断**，保留
  3. **环境变量回退读**：新名 `DSHBB_*` 优先、旧名 `BLENDERMCP_*` **回退**（用户已设的 key 不能失效）—— 注释标注"兼容回退"
  4. `harveyxiacn` / `blender_mcp_addon`：**另一个第三方实现**的判别标记（协议 id `category-action` 本身中性），仅出现在兼容回退分支
- **插件（runtime/docs）内的允许位**：
  1. 兼容回退分支里的旧 addon 标识 `blendermcp_*` / `blendermcp_server`（注释标注"旧 addon 回退"）
  2. `'ahujasid'` 作为**已弃用别名**（归一化为 `'flat'`），注释标注
  3. 评估/对比文档里的**上游归属叙述**（`docs/上游整合评估-mcp-for-blender与blend-ai.md` 连文件名保留、`docs/宿主集成层评估-*.md` 的上游出处、`CHANGELOG.md` 的来源/对比、`runtime/viewstore.mjs` 的 MIT 出处注释）—— 用户**未**选择去署名
- **不允许**（必须清零）：
  1. addon 里除上述允许位之外的任何 `blendermcp` / `BlenderMCP` / `BLENDERMCP_` / `MCP for Blender` / `BlenderMCP:` 日志前缀
  2. 插件 UI / `/doctor` / `/status` / `/commands` / 错误与提示文案里的上游项目名
  3. 文档里把上游当**品牌或卖点**的表述
- **跨制品一致性**：addon 改名的同时，插件侧对 `dshbb_server` / `dshbb_use_*` / 模块名启发式（`launch.mjs` 的 `"mcp"` 匹配）必须同步支持新名 —— 否则重启 Blender 后通道断。
- 历史重写后：`git log --all -p | grep` 亦不得命中（v2.0.0 之后的提交；重写只清理**当前分支可达**的历史）

## 5. 用户侧必须知道的三件事（Lead 在最终报告里必须说明）

1. **Blender 要重启**，且改名后 addon 的**模块名变了** ⇒ Blender 旧的"已启用插件"记录（`blender_mcp`）会失效，需要在 Blender 偏好设置里**重新启用 `DSH Blender Bridge`**（旧条目是死引用，可移除）。
2. **以后升级上游 addon 会打回原形**（它用 `blendermcp_*`）；插件的双名回退能让通道继续工作，但 addon 的显示名会变回 `MCP for Blender`。
3. **历史重写会改掉所有 commit SHA**（含用户原有 3 个提交）；任何已有克隆/分支会分叉。备份：`.scratch/blender-host-integration/rebrand-backup-*/`（bundle + 工作树 + 活 addon 原件 + 远端 SHA）。
