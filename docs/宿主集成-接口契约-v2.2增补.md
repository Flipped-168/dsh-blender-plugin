# v2.2 增补：点选无人应答快速失败（watcher）

> 状态：**向后兼容的增量**。既有 `/host/*` 字段语义、`blender_rt_pick` 入参与正常等待行为不变；
> 只**新增**字段，并在「没有任何 UI 轮询」时把等待从 120–600 s 压到约 2.5–3 s。
> 关联：[宿主集成接口契约](宿主集成-接口契约.md) §7.2/§7.4、[TUI 适配](TUI-适配.md)。

---

## 1. 为什么

`blender_rt_pick` 是阻塞式交互，旧实现只能从 `/host/pick/result` 看到
`pending` / `expired`，**无法区分**：

- 用户看到了面板，只是没点；
- 宿主根本没有可应答 UI（dsh-TUI 无面板 / 面板注册失败 / Web 侧栏没打开）。

两种情况的旧回执都是「等 `timeout_s`（默认 120 s，最多 600 s）后超时」，文案还写成
「用户没点」，模型可能让用户反复重试。TUI 更没有 Web 侧栏，这个问题是必现的。

## 2. 后端增量（`runtime/server.mjs`，零 Blender 往返）

### 2.1 记录「面板还活着」

只记录**面板专属**的 GET 路由：

| 路由 | 记录 | 说明 |
|---|---|---|
| `GET /host/view/latest` | ✅ | 面板常规轮询（1500 ms / stale 600 ms） |
| `GET /host/view.png` | ✅ | 面板取图 |
| `GET /host/pick/request` | ✅ | 面板取 pending（2000 ms） |
| `GET /host/ready` | ⚠️ 仅合法 Web Origin | 代表 Web 页面还活着（侧栏可以收起）；无 Origin 的健康检查/调试 curl 不算。合法 Origin 用 `HOST_ORIGIN_RE`（loopback 或精确 `dsh-app://app`） |
| `GET /host/pick/result` | ❌ | **模型侧**轮询；记了会让工具自己伪装成 UI |

- TTL：**10000 ms**（面板 1.5–2 s 一轮；捕获/取图最长 5 s，留足两个 tick）。
- `kind` 只是诊断标签：面板可带 `?client=web|tui`，缺省 `unknown`。

### 2.2 新增字段

均为**附加字段**，旧客户端忽略即可：

```jsonc
// GET /host/ready
{ "ok": true, "ready": true, "addon": true, "protocol": 11, "backend": "2.1.0", "reason": null,
  "ui": { "seen": true, "age_ms": 450, "kind": "tui" } }

// POST /host/pick/request
{ "ok": true, "request": { "...": "..." },
  "watching": { "seen": false, "age_ms": null, "kind": null } }

// GET /host/pick/request
{ "ok": true, "request": null, "watching": { "seen": true, "age_ms": 320, "kind": "web" } }

// GET /host/pick/result
{ "ok": true, "state": "pending", "object": null, "objects": [], "error": null,
  "watching": { "seen": true, "age_ms": 320, "kind": "web" } }
```

字段语义：

| 字段 | 类型 | 语义 |
|---|---|---|
| `seen` | boolean | TTL（10 s）内是否有过面板轮询 |
| `age_ms` | number\|null | 距最后一次面板轮询的毫秒数；`null` = 从未见过 |
| `kind` | string\|null | 最近一次面板轮询带的 `client` 标签（诊断用） |

## 3. 工具行为（`blender_rt_pick`）

1. 发请求后记 `pickStartedAt`，照旧每 400 ms 轮询 `/host/pick/result`。
2. **宽限 2500 ms**（`PICK_NO_UI_GRACE_MS`）：给 TUI 面板 `auto-open` + 首次轮询留一个 tick；
   宽限内即使 `watching.seen=false` 也不判死。
3. 宽限后若 `watching.seen === false`：
   - `POST /host/pick/cancel { reason: "no-ui" }`；
   - 立即返回可读回执，明确「这不是用户没点」，并建议改用 `blender_rt_do` 列对象或直接问名字。
4. `watching.seen === true` 时行为**完全不变**：继续等到用户点击、`timeout_s` 或取消。
5. 旧后端没有 `watching` 字段 → 保持旧行为（不会把字段缺失误判成无人应答）。

实测（本机，独立后端 9887，无面板轮询）：

```text
PICK 未检测到可应答的视口面板：请求发出后 3s 内没有面板在轮询 /host/*（从未见过面板轮询）；请求已作废。
可能原因：面板未打开、Web 页面在后台、dsh-TUI 面板注册失败，或宿主 open 被限速。
让用户打开/切回视口面板后再试；或改用 blender_rt_do 列 bpy.data.objects / 直接问用户对象名。
```

有 watcher 时（同一后端，1 s 一次 `/host/view/latest`）仍按 `timeout_s=5` 等满 5 s，返回原超时语义。

## 4. 判据

| # | 判据 | 判定 |
|---|---|---|
| 1 | 无 watcher：请求后约 2.5–3 s 返回 no-ui | 工具回执含「无人应答」；请求 state=`cancelled` |
| 2 | 无 watcher：不会等满 `timeout_s` | 实测 2.8 s（`timeout_s=30`） |
| 3 | 有 watcher：不提前结束 | 实测 5.2 s（`timeout_s=5`），返回原「PICK 超时」 |
| 4 | 宽限后才开始轮询：不误杀 | 单测「auto-open 晚到」 |
| 5 | `/host/pick/result` 不刷新 watcher | 单测 + 工具空等场景（结果轮询不产生 `seen=true`） |
| 6 | 旧后端（无 `watching`）不误杀 | 代码分支：`watching` 缺失即跳过 |

单测：`node tests/pick_presence_selftest.mjs`（5/5）。
集成：`tests/host_cors_selftest.mjs` 46/46；`tests/host_routes_selftest.mjs` 的判据 26 空 jobs 红是既有测试问题，与 v2.2 无关。

## 5. 未覆盖 / 行为变化

- **Web / 桌面端**：`/host/ready` 带合法 Origin 时算 watcher，所以「页面可见、侧栏收起」仍按旧语义等到 `timeout_s`；
  页面关闭/切到后台、侧栏不再轮询且没有 view/png 请求时，才会按 v2.2 快速失败。README/TUI 文档不再声称
  「Web 行为不变、/host 字段没改」——`ui`/`watching` 是新增字段，`blender_rt_pick` 的等待行为也已改变。
- 浏览器标签页被切到后台时，`setInterval` 可能被节流；`seen` 会按 TTL 变 false，可能提前 no-ui。
  这是有意的取舍：宁可让模型早停，也不空等 120 s。用户切回标签页再调用即可。
- 多选请求同样适用 fail-fast；Web 用「完成(N)」，TUI 面板用 `d` 收单（本栈已补）。
- 没有新增 `/host/*` 路由，也没有改 `runtime/engine.mjs`（避免与 #21 冲突）。
