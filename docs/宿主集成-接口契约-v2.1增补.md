## §8.1 面板内缩放 / 平移（**纯客户端**，不改后端协议）

**设计要点**：面板显示的是 `POST /host/view/capture` 抓的**静态 PNG**（"用户视口现在这一帧"）。缩放/平移是**本地视图变换**，不动 Blender、不动用户视口。

- 状态：`view = { zoom, tx, ty }`；`zoom ∈ [1, 8]`（1 = 适配显示），`tx/ty` 为像素平移
- 交互：**滚轮**以光标为锚点缩放；**按住拖拽**平移；**双击**或「⟲」按钮复位到 `{1,0,0}`
- 渲染：对图片容器做 `transform: translate(tx,ty) scale(zoom)`（`transform-origin: 0 0`）
- **必须做逆变换**：点击选物时把屏幕坐标 → 图片原始归一化坐标
  ```
  rect = container.getBoundingClientRect()          // 容器 = 未变换的图片区域
  ix = (clientX - rect.left - tx) / zoom            // 图片内像素
  iy = (clientY - rect.top  - ty) / zoom
  x  = ix / naturalWidth ;  y = iy / naturalHeight  // 归一化 0..1，照 §7.2 发给 /host/pick/answer
  ```
  命中判定前要 `clamp(0,1)` 且**落在图外就不发请求**（避免把画布外的点击投到场景里）
- **捕获分辨率提高**：`AUTO_CAPTURE_MAX_SIZE` 与手动捕获的 `max_size` 提到 **1600**（原来 560/1000 级别）—— 否则放大只是把低清图拉大，点小零件照样点不准。这是缩放**有意义**的前提。
- 选物标记（上次点中的十字/圈）必须画在**同一变换坐标系**里，否则放大后标记会飘。
- **不引入**：轨道旋转 / 改相机 / 改 shading（那属于"改用户视口"，越界）。要看别的角度用模型侧 `blender_rt_see`。

## §8.2 多选零件（**后端协议 + 客户端 UI**，向后兼容）

原则：**单选的现有语义一个字节都不许变**；多选是**新增模式**。

### 请求体新增字段
| 路由 | 字段 | 默认 | 语义 |
|---|---|---|---|
| `POST /host/pick/request` | `multi: boolean` | `false` | `true` = 多选模式 |

### 多选模式下的应答语义
| 动作 | 请求 | 命中时 | 落空时 |
|---|---|---|---|
| 加选 | `POST /host/pick/answer {requestId, seq, x, y}` | **加入** `objects`（按对象名去重），**状态保持 `pending`**；回 `{ok:true, state:"pending", added:"<name>", objects:[…]}` | `{ok:false, state:"pending", error:"empty"}` —— **不结束请求** |
| 取消某件 | `POST /host/pick/remove {requestId, name}` | 从 `objects` 移除；回 `{ok:true, state:"pending", objects:[…]}` | — |
| 完成 | `POST /host/pick/answer {requestId, done:true}` | `state:"answered"`，`objects` 冻结；回 `{ok:true, state:"answered", objects:[…], object:<首个或 null>}` | — |
| 取消整单 | `POST /host/pick/cancel {requestId, reason}` | 同 §7.2（`cancelled`），新增 `reason:"superseded"` 不变 | — |

- **单选模式（`multi:false`）完全照 §7.2**：`answer` 命中即 `answered` + `object`；点空处 = `answered` + `object:null`（"用户明确表示没有"）。
- **`GET /host/pick/result`** 在两种模式下都回：`{ok, state, object, objects, error}`。单选时 `objects` = `object ? [object] : []`。
- **错配（`scene_mismatch` / `unknown_seq`）在两种模式下都不结束请求**（照 §7.6 判据 13）。
- `objects` 元素形状**照 §1.5 pick 的既有形状**（含 `name` 至少；其余字段与单件一致）。
- 全局仍**至多一个 pending**；`superseded` / `expired` / `cancel` 语义照 §7.2。

### 模型工具 `blender_rt_pick`
- 入参新增 `multi?: boolean`（默认 false）。
- 单选：返回照旧（对象名）。
- 多选：阻塞到 `answered`，返回**对象名数组**（`objects[].name`），并在文本里列出全部。

### 客户端 UI
- 面板顶部加「**多选**」开关（默认关）。开启后每次点击**累加**，面板列出已选（每项带「✕」移除），按钮显示「**完成(N)**」。
- 「加入消息」在单选模式照旧插一件；多选模式插入**全部**已选。
- 多选模式下的空点**不结束**、只提示"此处没有物体"。

## §8.3 headless 作业区（**面板可见 headless 进度**）

背景（用户第 1 个问题的根因）：`blender_rt_headless` / `blender_rt_job` 跑的是**独立 `blender -b` 进程**，有自己场景，**不碰 GUI** ⇒ GUI 视口与面板永远看不到它。作业注册表在**后端进程**（`engine.job`，`runtime/engine.mjs`），所以面板走两条**只读** `/host` 路由即可。

### 新增只读路由
| 路由 | 查询 | 回包 |
|---|---|---|
| `GET /host/jobs` | `?limit=20`（1..100，默认 20） | `{ok:true, jobs:[<trimmed job>], running:<n>}` |
| `GET /host/jobs/log` | `?id=<id>&tail=8000`（tail 1..200000，默认 8000） | `{ok:true, id, stdout:<str|null>, stderr:<str|null>, job:<trimmed job>}` |

**`<trimmed job>` 字段（逐字）**：`id, kind, status, runId, pid, pidAlive, ms, timeoutMs, outdir, logDir, exitCode, signal, stage, stageName, stageAgoMs, lastOutputAt, idleMs, lines, logBytes, resultJson`
- 数据源：`engine.job.list()` / `engine.job.status(id)` / `engine.job.collect(id, tail)`（**已存在，不要重造**）
- **必须裁掉** `resultJson` 之外的大字段（`script`、`resultPath` 之类按需保留但不得把整包原样吐出）；`resultJson` 若超大按 `≤8 KB` 截断并置 `resultTruncated:true`
- 排序：`running` 在前，其余按 `ms`/时间倒序；`limit` 严格夹取（照 §1.x 的 clamp 口径，非法值回默认，不报错）
- **零 Blender 往返**：这两条只读后端内存/磁盘，**不得**触发任何 addon 调用（判据要证明 `metrics.calls` 增量 0）
- CORS 照既有口径（只对 loopback Origin 回显）

### 客户端 UI
- 面板加「**作业**」区：列出 job（`status` / `stageName` / 已跑时长 / `idleMs` / `lines`）；点一条**展开日志尾部**（调 `/host/jobs/log`）。
- **有 running 时**才轮询（`/host/jobs`，建议 2 s）；全空闲时降到 10 s 或停（省资源）。
- 空态文案要说明为什么：*"headless 作业在独立进程里跑，视口/面板看不到画面；这里看状态与日志"*。
- 渲染大日志要**限高 + 可滚动**，别把面板撑爆。

| # | 判据 | 判定方式 |

## §8.6 实现注记

1. **缩放不增加信息量**：放大的是同一张 PNG。真正的精度来自 §8.1 的"捕获 `max_size` 提到 1600"，两件事必须一起做。
2. **多选不要改单选的返回形状**：`object` 单值字段在两种模式下都存在（多选时给首个或 `null`），否则 §7 的既有测试与模型侧解析会碎。
3. **作业区只读**：`/host/jobs*` 只读后端台账，**不**提供 kill/重跑（那是模型侧 `blender_rt_job` 的职责，面板不做写操作 —— 与 §3"面板不写场景"一致）。
4. **`/host/*` 不进 op 目录**：新增路由不得出现在 `blender_rt_plan(op="catalog")`，以保住 `tests/capability.lock.json`（28 family / 186 op / 16 工具不变）。
5. **未证实项要登记**：客户端半边需**重启 DSH** 才生效；面板内缩放/拖拽的真实手感、`getBoundingClientRect` 在侧栏里的实际值，都属"重启后由用户确认"。
